# 실행·검증 보고서

검증일: 2026-11-07. 시험 환경 설치와 Kafka 기동은 수행하지 않았습니다.

## 실행하여 확인한 것

- Q08~11 정답 함수의 오프라인 계약 테스트 26개 통과. 실제 정답 모듈을 불러 실행했고 Kafka 객체만 테스트 대역으로 바꾸었습니다. 생성자 옵션·Admin 생성 호출·키/값·UTF-8·빈 입력·빈 값·전송 완료 확인·flush·오류 전파를 검사했습니다. 자세한 로그는 제작자료/test_정답.txt에 있습니다.
- 응시용 같은 테스트는 미구현 NotImplementedError로 실패합니다. 테스트 로더는 작동하고 문법 오류로 실패한 것이 아닙니다. 시작 파일의 함수·경로와 테스트 연결을 확인했습니다.
- 모든 Python 파일의 구문 검사, 문항 12개·배점 100점·권장 시간 110분 집계, 정답 명령 파일의 모든 실행 줄이 docker로 시작하는지 확인했습니다.
- Kafka Compose는 docker compose config --quiet 재검사에서 종료 코드 0을 확인했습니다. 초기 제한 시간 40초 검사에서는 Docker CLI 응답 지연으로 시간 초과가 났습니다. 이 기록은 제작자료/verification.json에 구분했습니다.
- 웹 Compose의 응시용·정답 설정도 config --quiet 재검사를 통과했습니다. 총 3개 Compose 파일의 구문·구성 해석을 확인했으며 실제 컨테이너 기동 검증은 아닙니다.
- 문제 PDF 7쪽, 정답 PDF 13쪽을 모두 렌더링했습니다. 전체 페이지 모음 및 긴 코드 페이지를 확대해 한글·들여쓰기·줄바꿈·잘림을 확인했고 문항 12개가 양쪽 PDF에 모두 있음을 검사했습니다. 기록은 제작자료/pdf_checks.json에 있습니다.

## 실제로 실행하지 못한 것

Docker CLI는 존재하고 Compose 버전은 v5.6.1로 확인되었습니다. 그러나 Docker Server 조회는 dockerDesktopLinuxEngine 파이프를 찾을 수 없다는 오류를 반환했습니다. 따라서 Docker 엔진·컨테이너를 사용한 검증은 진행하지 않았습니다.

- Docker 이미지 다운로드·Dockerfile 빌드·컨테이너 기동
- Flask 외부 포트 응답·웹 Compose DNS·마운트 결과·실제 Linux 로그 명령
- cp-kafka:7.6.1 KRaft 부팅과 healthy 상태
- 토픽 생성/변경/삭제, 실제 메시지 송수신, 그룹 오프셋·리밸런스
- 지정 Python 3.10 컨테이너와 kafka-python 2.0.4의 실제 브로커 연결

오프라인 Python 함수 테스트는 로컬 Python 3.12.2에서 표준 라이브러리와 테스트 대역으로 실행했습니다. 컨테이너용 Python 3.10 환경과 동일하다고 주장하지 않습니다. 구문은 Python 3.10 호환 형태로 작성했습니다. Kafka 설치나 Setup.exe 다운로드는 하지 않았습니다.

## 추후 재현 가능한 확인

응시용/README.md에 Docker만 사용하는 준비·실행·정리 명령이 있습니다. support/verify_live.py는 실제 Kafka에서 파티션 수, 메시지 멀티셋, 같은 키의 파티션, 변환 결과를 검사합니다. orders와 pipeline 두 모드를 제공합니다. 이 스크립트는 제공했으나 실제 실행 결과는 아직 없습니다.
