# Q10 서술형 (10점, 각 2점)

각 질문에 2~4문장으로 답하세요.

## (1) Dockerfile의 `RUN` 과 `CMD` 의 차이를 실행 시점 기준으로 설명하고, Q03 Dockerfile에서 각각 어떤 일을 하는지 쓰세요.

답: RUN은 docker build 시점에 실행되어 그 결과(설치된 패키지 등)가 이미지 레이어로 저장된다. CMD는 빌드 때는 실행되지 않고, docker run으로 컨테이너가 시작될 때 실행할 기본 명령을 지정한다. Q03에서 RUN은 pip install로 flask를 이미지에 설치하고, CMD는 컨테이너 시작 시 python app.py로 서버를 띄운다.

## (2) Q03의 포트 연결 옵션(호스트 8000 ↔ 컨테이너 5000)을 예로 들어 옵션 값의 앞 숫자와 뒤 숫자의 의미를 쓰고, Q03의 `app.run(port=5000)` 만으로는 호스트에서 접속되지 않는 이유를 쓰세요.

답: 앞의 8000은 호스트 PC 포트, 뒤의 5000은 컨테이너 내부 포트로, 호스트 8000으로 들어온 요청을 컨테이너 5000으로 전달한다. host를 지정하지 않으면 Flask는 127.0.0.1(컨테이너 자기 자신)에서만 요청을 받으므로, 포트 포워딩으로 들어온 외부 요청을 받지 못한다. host="0.0.0.0"으로 모든 인터페이스에서 받도록 해야 한다.

## (3) 아래는 브로커 3개 환경에서 복제 계수 3인 토픽의 describe 결과입니다. Leader, Replicas, Isr의 의미를 쓰고, 브로커 2번이 중단되었을 때 Isr이 어떻게 바뀌며 메시지를 계속 읽을 수 있는지 쓰세요.

```
Topic: test5-topic  Partition: 0  Leader: 2  Replicas: 2,0,1  Isr: 2,0,1
```

답: Leader는 해당 파티션의 읽기/쓰기를 담당하는 브로커(2번), Replicas는 복제본이 저장된 브로커 목록(2,0,1), Isr은 리더와 동기화된 복제본 목록이다. 2번이 중단되면 Isr에서 2가 빠지고(예: Isr: 0,1) 남은 동기화 복제본 중 하나가 새 리더가 된다. 복제본이 남아 있으므로 살아 있는 브로커(예: 9093)로 접속하면 메시지를 계속 읽을 수 있다. RF가 3이면 최대 2대(RF-1) 장애까지 견딜 수 있다.

## (4) Q08에서 같은 키(seoul 등)가 항상 같은 파티션에 들어간 이유와, Q07처럼 키가 없는 메시지의 파티션 결정 방식의 차이를 쓰세요.

답: 키가 있으면 키의 해시값을 파티션 수로 나눈 나머지(hash(key) % 파티션 수)로 파티션이 정해지므로, 파티션 수가 바뀌지 않는 한 같은 키는 항상 같은 파티션에 들어간다(순서 보장 가능). 키가 없으면 Sticky 파티셔너가 한 파티션에 배치가 찰 때까지 몰아서 보내고, 배치가 차면 다른 파티션으로 바꾼다.

## (5) Q08-2 컨슈머를 같은 `group_id="region-checker"` 로 다시 실행하면 아무 메시지도 출력되지 않습니다. 이유를 쓰고, 처음부터 다시 읽으려면 어떻게 해야 하는지 쓰세요. 또 파티션이 2개인 토픽을 같은 그룹의 컨슈머 2개가 구독하면 메시지가 어떻게 나뉘는지 쓰세요.

답: enable_auto_commit=True로 첫 실행에서 읽은 위치(오프셋)가 그룹 이름으로 커밋되었기 때문에, 같은 그룹은 커밋된 다음 위치부터 읽어 새 메시지가 없으면 출력이 없다. auto_offset_reset="earliest"는 커밋된 오프셋이 없을 때만 적용된다. 다시 처음부터 읽으려면 새로운 group_id를 쓰면 된다(그 경우 earliest 적용). 같은 그룹의 컨슈머 2개는 파티션을 하나씩 나눠 맡아, 각 메시지는 그룹 안에서 한 컨슈머만 받는다(분산 소비).
